# Tracker

Tracker 功能类似 Git，本地储存一份追踪列表，拉取远端变更并同步。  
可以管理多个列表，每个列表可任意组合单曲、歌单、专辑来源。

## 新建

使用 `vncmd tracker "名称"` 即可，这会创建一个该名称的 Tracker。  
如果这个名字存在，则会显示这个 Tracker 的信息。

Tracker 的名称为文件夹名（`.vSoft/vncmd/tracker` 下的子目录名），仅允许大小写字母、数字、短横线和下划线。且禁止重复。

建立完成后，你可以在 `.vSoft/vncmd/tracker/<名称>` 目录下找到 `settings.toml` 配置文件。默认为空的预设，需要手动编写。  

## 配置

`[tracker].description` 用来设置一个说明，仅供展示用，方便你记录这个列表的用途。

下面三个 `sources` 为单曲/歌单/专辑的列表。  
你可以将对应项目的 `id` 放在 `ids` 数组，允许多个值。

程序拉取时会按 `sources` 逐条处理，每个来源中的 `ids` 会被遍历。  
同一首歌出现在多个来源时，缓存中会记录 `at` 字段标记所有来源。

## 使用

```bash
vncmd tracker "名称" -f         # 拉取并交互式解决冲突
vncmd tracker "名称" -d         # 下载全部已记录的曲目
vncmd tracker "名称" -d --diff  # 下载自上次拉取以来新增的曲目
```

### 解决冲突

`-f` 拉取后列出三类变更，需要手动解决冲突：

- **新增**：远端列表中存在，但本地不存在
- **移除**：远端列表中不存在，但本地存在
- **变更**：ID 相同但曲目名称不同

已下架的曲目会被自动检测并单独提醒，不参与冲突解决（视为已存在）。

`--fetch-auto` 自动接受全部变更，直接镜像上游。每次写入缓存前自动备份，可从 `.bak` 回滚。

## 完整命令

```bash
vncmd tracker <名称> [-f | --fetch-auto] [-d] [--diff] [--dry-run] [-q 音质] [-o 目录]
```

| 参数 | 简写 | 说明 |
| --- | --- | --- |
| `--fetch` | `-f` | 拉取，交互式解决冲突 |
| `--fetch-auto` | `/` | 自动同步，镜像上游 |
| `--diff` | `/` | 下载自上次拉取以来新增的曲目，需配合 `-d` |
| `--download` | `-d` | 下载 Tracker 中的全部曲目 |
| `--dry-run` | `/` | 仅预览，不实际下载 |

不带参数时，展示 Tracker 简介。
